# 博客搬到后花园（192.168.1.154）· 迁移方案

> 2026-11-21 实地盘点后写的。命令都在服务器上只读跑过，数字是真的。

## 0. 先说结论

**搬家很简单，难的是「搬过去之后谁对公网提供服务」。** 三个方案，成本差一个数量级：

| 方案 | 做法 | 读者访问 | 工作量 |
|---|---|---|---|
| **A. 只搬源码** | 服务器 = 第二个开发机，构建发布仍走 GitHub Actions → Pages | 不变（v4+v6，全球 CDN） | **30 分钟** |
| **B. 服务器自建** | 服务器本地构建 + Caddy 直接对外，GitHub 只当备份 | 只有 IPv6 的人能开 | +1~2 小时 |
| **C. 双轨** | A 为主站，另在服务器起一个自建版（内网或专属域名） | 主站不变，自建站自己看 | A + B |

**我推荐 C 的轻量版**：先把 A 做完（保证随时能干活），如果之后想自己托管，再加 B 那层。理由见 §2。

## 2. 三个关键技术判断

**① 纯 IPv6 是硬伤。** 后花园只有 IPv6，博客如果只挂在这台机器上，很多访客打不开——部分蜂窝网络、公司内网、双栈失败的用户都会卡住。GitHub Pages 有 IPv4+IPv6 加全球 CDN，这一层免费且零维护。**这就是我建议「自建只作附加」的原因，不是为了省事。**

**② 构建负载可以忽略。** 这份博客构建实测 60 ms、峰值内存几十 MB。和 `llama-server` 抢资源？不存在。真正要避开的只有那条老规矩：llama 和 MC 服不同时跑。

**③ 服务器 GitHub 直连是通的。** 记忆里 Fedora 曾经要挂 `gitclone.com` 镜像，这次实测直连正常，所以 clone / pull / push 都能走原路。

## 3. Stage 1（方案 A，30 分钟，无风险）

1. **装 Hugo**：官方 0.169.0 extended linux-amd64 二进制丢进 `~/.local/bin`。
   - **版本必须和本地一致**，Hugo 跨小版本会改 SCSS/模板行为，你那套包豪斯样式是手写 SCSS，版本漂移会直接花掉。
   - Fedora 源里的 hugo 版本偏旧，不用。
2. **选目录**：`/mnt/data2/blog`（776 G 可用，别放系统盘）。
3. **clone**：`git clone https://github.com/KaiTeeDreamChai/....git`
4. **验证构建**：`hugo --minify --gc`，对比本地产物文件数（现在 64 个静态文件 + 页面）。
5. **配推送**：生成一对 deploy key 加到 GitHub（只给这一个仓库）——比存 PAT 干净，泄露面小。
6. **写个 `blog.sh`**：`git pull && hugo --minify --gc`，一行命令出站。

做完这步：服务器能拉、能改、能推、能构建；**发布链路完全不变**，Pages 继续工作。

## 4. Stage 2（方案 B，可选）

1. `sudo dnf install caddy`，`setcap`/端口绑定走 systemd 自带权限（Caddy 可以直接绑 80/443）。
2. Caddyfile：
   ```
   :80 {
       root * /mnt/data2/blog/public
       file_server
       encode gzip zstd
   }
   ```
3. **SELinux 是必踩的坑**：`/mnt/data2` 不在 httpd 的默认上下文里，Caddy 会 403。用
   `sudo semanage fcontext -a -t httpd_sys_content_t "/mnt/data2/blog/public(/.*)?" && sudo restorecon -Rv /mnt/data2/blog/public`
4. **防火墙**：现在 INPUT 全 ACCEPT、IPv6 公网直连。开 80/443 之前先把 `firewalld` 规则写清楚，只放行必要端口，别顺手把 22 或 MC 面板也放给全网。
5. 内网访问 `http://192.168.1.154` 验收。

## 5. Stage 3（对外，需你拍板）

- 域名：`92homelab.dynv6.net` 是 IPv6-only。**如果要用它，等于接受「只有 IPv6 访客能看」**。
- 想对外又想兼容 IPv4，得二选一：
  a) 买个域名 + 用 Cloudflare 免费代理（Cloudflare 有 IPv4 入口，回源走 IPv6）——这是最实际的解法；
  b) 只给内网/自己用，公网继续 Pages。
- TLS：dynv6 + Caddy 可以走 HTTP-01（IPv6，需 80 端口对公网开放），或用 dynv6 API 走 DNS-01。

## 6. 预判的坑

| 坑 | 说明 |
|---|---|
| Hugo 版本漂移 | 服务器必须 0.169.0 extended，和本地一致 |
| SELinux 403 | `/mnt/data2` 要打 `httpd_sys_content_t`，否则 Caddy 读不到 |
| 公网暴露面 | 现有 INPUT ACCEPT + root 密码 SSH 是历史遗留，开新端口前先收口 |
| 动态 IPv6 | 地址会变，靠 ddns-go 的 AAAA；自建站别写死 IP |
| 备份 | 服务器不自带备份，建议挂到现有 `mc-backup` 或单独 timer |
| 别删 Actions | 它是发布链路，也是回滚路径 |

## 7. 需要你定的三件事

1. **要哪个方案**：A（只搬源码）/ A+B（加内网自建）/ A+B+C（对外自建）
2. **对外的话域名怎么解决**：dynv6 纯 IPv6 够用，还是上 Cloudflare 换 IPv4 入口
3. **GitHub 凭据**：服务器生成 deploy key（我推荐），还是你已有 PAT 直接给

方案定为 **A+B**（源码搬过去 + 内网自建），凭据用服务器上的 `gh`（token 经 SSH stdin 传入，未落盘明文）。

| 步骤 | 结果 |
|---|---|
| GitHub 认证 | 服务器 `gh` 已登录 `KaiTeeDreamChai`（`gh auth setup-git`） |
| 克隆 | `/mnt/data2/blog`，HEAD `ade3a17`，373 文件 |
| Hugo | `~/.local/bin/hugo` v0.169.0 **extended** linux/amd64（与本地严格同版） |
| 构建 | 44 ms，87 个产物文件 —— **与本地完全一致** |
| Web 服务 | `caddy 2.11.4`，`/etc/caddy/Caddyfile` 服务 `/mnt/data2/blog/public`，已 `enable --now` |
| SELinux | `/mnt/data2/blog/public` 已打 `httpd_sys_content_t`，否则 403 |
| 防火墙 | `FedoraWorkstation`(enp5s0) 与 `nm-shared`(wlp6s0) 两个 zone 都放行 http |
| 访问 | 内网 `http://192.168.1.154/` 200，`/about/` `/archives/` `/search/` 均 200，未知路径 404 走自定义页 |
| 运维脚本 | `~/blog.sh`：`git pull --ff-only && hugo --minify --gc` |

**踩到的坑**：从 Mac 访问 80 被拒（22 正常）。原因不是防火墙没开，而是 Mac 当时连的是**服务器自己开的热点**（`10.42.0.x`，走 `wlp6s0`），而 `wlp6s0` 属于 `nm-shared` 区域，该区域只放了 dhcp/dns/ssh。补 `http` 后正常。走 LAN（`enp5s0`）时是另一个区域，两者都要开。
